RECONCILIATION

Auditable record reconciliation

Merge imperfect exports without hiding uncertainty

2,070 source rows · 820 enrichment records · 130 review cases

Problem

Two systems export overlapping records, but one source lacks a reliable email key. A naive join drops matches, duplicates records or attaches one person's attributes to another.

Method

Normalize identity fields, block candidates by email/name/IP, apply explicit evidence rules, require a separation margin and preserve a review queue. Conflicting emails, uncertain dates and multiple records claiming the same target never silently overwrite the source.

CSV exports → normalization → candidate blocks → evidence rules → matched / review / unmatched → audit + output

Deliverables

Order-preserving merged CSV; duplicate ledger; per-candidate evidence; match decisions; source hashes and policy audit.

INGESTION

Replay-safe webhook analytics

Accept signed events and count each payment once

Duplicate and worker replay leave totals unchanged

Problem

Webhook senders retry events. Duplicate deliveries, conflicting IDs and inconsistent money handling can corrupt dashboard totals even when the endpoint appears to work.

Method

Authenticate the raw body with HMAC and a timestamp window, validate the schema, store a canonical hash and event ID, and commit receipt plus outbox together. A separate worker atomically updates daily currency totals and marks work complete.

Signed HTTP event → freshness + schema → event ledger + outbox → transactional worker → daily analytics

Deliverables

Flask endpoint; durable event ledger; transactional outbox; retry/dead-letter state; UTC daily aggregates; duplicate/concurrency tests.

RETENTION

Retention outreach prioritization

Turn model scores into a bounded review queue

2.40× lift at 20% contact capacity

Problem

A retention team has limited outreach capacity. Accuracy alone does not show whether the first customers reviewed are more likely to churn than a random contact list.

Method

Compare a base-rate predictor, logistic regression and a bounded random forest. Fit preprocessing inside each training pipeline, select on validation PR-AUC, choose the outreach threshold from validation only, then evaluate the untouched test set.

Customer snapshot → train/validation/test → fitted preprocessing → model selection → capacity threshold → holdout scores + API

Deliverables

Ranked customer scores; PR-AUC/ROC-AUC; confusion matrix; lift at 20%; calibration bins; permutation importance; split manifest; schema-validated scoring API.

DEMAND

Hourly demand estimation

Plan with a baseline, error slices and uncertainty

25.2% lower holdout MAE than the historical baseline

Problem

Rental operations need hourly demand estimates for staffing and availability. Random train/test splits can hide time drift and make a model look better than it will on a future period.

Method

Train on 2011, select and estimate residual widths on Jan–Jun 2012, and test on Jul–Dec 2012. Compare Poisson and boosted regressors to a historical hour/weekday baseline, add rolling training checks and report error by hour.

Hourly history → chronological split → baseline + candidate models → validation selection → frozen model → future-period error audit

Deliverables

Future-period predictions; baseline comparison; MAE/RMSE/WAPE; empirical interval coverage; rolling validation; hour-level error CSV and reproducible model artifact.

ROUTING

Customer request intent routing

Classify 77 intents and review uncertain requests

95.9% score-gated accuracy · 85.9% coverage

Problem

Support queues receive short, ambiguous customer questions. A classifier that always chooses a category can route vague, sensitive or unrelated requests incorrectly.

Method

Combine word and character TF-IDF features with a linear probabilistic classifier. Remove normalized duplicate conflicts and train/test overlap. Select a confidence/margin gate on validation, add lexical similarity and sensitive-request review checks, and return structured routing results with reference IDs.

Request text → partial redaction → intent + alternatives → review gates → team recommendation + reference IDs

Deliverables

77-intent model; macro-F1 and routed accuracy/coverage; per-intent report; out-of-domain probes; partial redaction; ranked alternatives; reference retrieval; authenticated routing API and duplicate-safe ticket receipt.
